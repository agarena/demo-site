甲层 · 新上架 2026

三个月前，我在 Lighthouse 里给这个博客打分，屏幕上跳出一个刺眼的红色数字：45。加载一个只有文字的页面要 2.8 秒，而访问者里有一半来自地铁里的手机。那天晚上我把台灯拧亮了一点，决定做一次彻底的性能考古。

先给字体瘦身

排查工具第一个揪出的就是字体：三套网络字体加起来接近 8MB，其中中文字体贡献了 95% 以上的体积。解法是子集化——用脚本扫描全部文章文本，只保留实际出现过的三千多个汉字，再把字体切成按需加载的分片。8MB 变成了 48KB。配合 font-display: swap 和 preload，文字先以系统字体出现，衬线体在后台悄悄就位。

关键 CSS 内联

第二步是把首屏渲染必须的那一小撮样式（不到 2KB）直接内联进 HTML，其余样式表异步加载。图片全部懒加载并用低分辨率的底色占位，避免布局抖动。没有框架，没有构建链，只有一个 300 行的生成器和两条朴素的规则：首屏的每一个字节都要自己证明存在的必要。

「快，是给读者最基本的礼貌。」

复测那天，分数停在 98，FCP 从 2.8 秒落到 0.7 秒。剩下的 2 分留给一个我还不愿意删掉的装饰性阴影。性能优化做到最后会发现：它不是技术清单，而是一种对读者的态度。

这个念头的起点很偶然：某天加班到凌晨，回家的出租车上看见一辆装满白菜的三轮车从我窗边掠过，车灯在湿漉漉的路面上拖出两条黄线。我忽然意识到，我从未见过这座城市醒来的过程。于是一周后，我定了四点的闹钟，跟着那辆三轮车走进了菜市场。

三轮车与白炽灯

四点的市场已经忙了两个小时。卸货的、劈骨头、发面的，各自有各自的节奏。鱼摊老板娘蹲在水盆前刮鱼鳞，动作快得像某种乐器演奏；豆腐坊门口蒸汽滚滚，白炽灯泡悬在蒸汽里，像一枚不会落下的月亮。我举着手机拍了九张照片，没有一张需要滤镜——那里本身就是暖色的。

五点四十，天亮了

天光是从市场的西头漫过来的。收摊的人把青菜上的水珠抖进阴沟，第一班公交车在巷口停下，穿校服的孩子和拎着鲈鱼的阿姨在同一站下车。两个世界在五点四十完成交接，像一次没人指挥的换岗。

回去的路上我想，一座城市的底层并不是写字楼，而是这些凌晨四点就亮着的灯。写代码的人管「无感」叫体验好，可那天的体验让我明白：有些「无感」，是因为有人在你看不见的时候把一切都备好了。

过去十年，滚动动画几乎等同于「引一个动画库」。但在 2026 年，CSS 自己就能做到这件事了：animation-timeline 让任何动画的进度直接绑定滚动位置——真正的零 JS。这篇笔记把入门需要的全部概念压缩成你可以一口气读完的长度。

两个函数

scroll() 把滚动容器的进度作为时间轴：页面顶部为 0%，底部为 100%。view() 则跟踪某个元素自身进入视口的过程。用法只有三行：animation-timeline: view()，再用 animation-range 指定起止区间。剩下的交给熟悉的 keyframes。

六个渐进增强案例

  • 顶部阅读进度条：一行 scaleX 动画绑定 scroll()；
  • 图片揭示：clip-path 随 view() 展开；
  • 章节标题的字重生长：font-variation-settings 随滚动加粗；
  • 数字看板：配合 CSS counter 的 counter-reset 计数；
  • 横向画廊的位移视差；
  • 目录高亮的滚动驱动版本。

兼容策略依然是老三样：@supports (animation-timeline: scroll()) 包住增强层，不支持的浏览器看到静态排版，一样完整。这也是本文所在网站的实际做法——你现在页面顶部的进度条，就是这三行 CSS。

乙层 · 2025 常翻

为什么有的长文让人「停不下来」，有的三屏就想退出？我把三个 Awwwards 获奖的长滚动网站逐帧拆了一遍，每秒截一图，标出每个元素进出的时刻。拆完发现，好动效的秘密不在动，而在节拍。

节拍：pinned 像定机位

三个案例都在关键章节用了「钉住」：背景不动，场景内的元素依次进场——数字滚动、图表生长、引言淡入。这本质上就是电影里的定机位长镜头：画面静止，戏在走。用户滚动的每一格，都被设计成了导演的每一帧。

留白与呼吸

第二个案例在章节之间留了整整两屏的空白，只有一个不断放大的数字。当初我以为这是浪费，逐帧对照后才发现：留白是乐谱上的休止符，没有它，前面的高潮就不成立。第三个案例则用背景色做情绪曲线——纸白、暮蓝、暖黑，颜色本身在讲故事。

动效是剪辑，不是特效堆叠。每章不超过三种动效，克制即高级。

这篇拆解后来直接决定了你现在看到的这个书架的节奏：入场两秒、动效各司其职、正文永远比装饰优先。

一年前的今天，我把「收藏」文件夹里的一千多条链接关掉，承认了一个事实：收藏等于读过的幻觉。于是开始种一座数字花园——所有笔记公开，按成熟度标注：种子（刚发芽的想法）、抽芽（整理过一半）、常青（成形的文章）。

一年后的收成

214 条笔记里，种子 78 条，抽芽 96 条，常青 40 条。让我意外的不是数量，而是流动：一年里有 31 条种子长成了抽芽，11 条抽芽开成了文章——包括你正在书架上看到的这一本。笔记不再是坟场，而是苗圃。

双链的副作用

双链最奇妙的地方不是「连接」，而是笔记之间开始互相点名：写「性能」时会撞见三个月前关于「排印」的一条旧想法，两条毫不相干的笔记合成了第三条。知识在你注意不到的地方自己发酵。

另一个收获是放弃完美主义。公开的草稿比私藏的完整更有价值——读者会顺着半成品找到你，而不是等你「准备好」。这也是「半成品」这个栏目存在的理由：这座花园永远施工中。

抽屉最里面躺着一台 2015 年的 Kindle Keyboard，电池鼓包换了新的之后，居然还活着。屏幕上停着五年前读到一半的《来自新世界》。我决定给它一次重生：不复活成一台「设备」，而是降级成一个「终端」——一个只能读文章的墨水屏终端。

越狱与换字体

老机型越狱出乎意料地顺滑，社区的维护者比我年纪还大的工具链依然在工作。第一步换字体：思源宋体，行距调到 1.8，页边距加宽——做完这些它突然从「电子设备」变成了「纸」。

只读文章的墨水屏终端

然后是砍功能：注销账号、屏蔽商店、禁掉浏览器。写了一个小脚本接住 calibre 的推送，再挂上定时任务，每天早上把我 RSS 里标记的长期文章排版后投递进去。它从此只做一件事：把我昨天存下的思考，在今天早上递给我。

改造完的第一个月，睡前刷手机的次数降到了零。十年前的屏幕替我挡住了十年的信息噪音——设备旧了，注意力反而新了。

打开任何一个 2026 年的设计趋势盘点，「衬线回潮」都会在列。但这不是审美的轮回那么简单——衬线体在屏幕上被委屈了三十年，如今是技术终于配得上它了。

分辨率还了它的笔锋

衬线体的灵魂在笔锋的粗细变化，而这恰恰是低分辨率屏幕最负担不起的东西。72dpi 的年代，宋体的衬线被压成一团黑疙瘩，于是我们全员无衬线。Retina 屏普及后，每英寸三百多个像素点足以还原运笔的提按，铅字时代的细节第一次在屏幕上完整落地。

可变字体：一套字轴，无限字重

第二记助攻是可变字体：一个文件里装着整条字重轴，标题可以用 800 的厚重、正文用 400 的安静，同一个字体的呼吸贯穿全篇。排印第一次在网页上拥有了「液体」的性质。

所以杂志感的回潮，本质是技术成熟与审美反弹的会师：当所有网站都长成同一个圆角卡片时，一副有笔锋的宋体标题，就是最响亮的态度。

起因是一句赌气：有一天构建这个博客的框架又发布了破坏性更新，我盯着 migration guide 忽然想——我只有十几篇文章，凭什么要伺候一套庞大的工具链？于是有了这个 90 天的周末项目：一个零依赖的静态站点生成器，你现在看到的每一页都是它生成的。

架构只有三步

核心 300 行，全用 Node 标准库：读 Markdown 文件，用一个 200 行的手写解析器处理标题、引用和代码块，套上 HTML 模板，写进输出目录。没有插件系统，没有配置文件，node build.js 是它全部的使用说明。

踩坑清单

  • Windows 与 Unix 的路径分隔符，让 glob 匹配翻车了三次；
  • UTF-8 的 BOM 头让第一篇标题渲染出了看不见的字符；
  • 增量构建的缓存失效策略，最终简化成「比对修改时间，可疑即重建」；
  • 中文换行规则：line-break: anywhere 千万不要用。

90 天最大的收获不是工具，而是一种确定感：依赖越少，夜晚越安静。下一次框架再搞破坏性更新，与我无关。

丙层 · 旧藏 2023—2024

改造前的书房是一个体面的仓库：飘窗上堆着纸箱，桌上的线缆结成蜘蛛网，唯一有生气息的是窗台一盆半死不活的仙人掌。2024 年冬天，我决定把这十平米改成「一个人的图书馆」——你现在浏览的这个网站的样子，就是这间书房的样子。

三层书架与一把旧椅

书架的木料来自旧货市场：两块老松木门板，砂纸打到 400 目，木蜡油擦了三遍。搁板的高度按书算过：最上层放大开本，中层顺手放常翻的，底层留给旧物。椅子是一把 90 年代的旧转椅，换了液压杆，坐上去有轻微的、令人安心的吱呀声。

灯光才是书房的灵魂

全部光源统一成 2700K：一盏吊灯负责整屋的底色，一盏读书灯负责桌面，再加一条藏在搁板下的灯带，给书脊打出一线暖光。三层光源、三种阴影层次——书房在夜里才有书房的样子。

改造用了一个月，预算不到两千块。完成后我在这张桌上写下了后来的一多半文章。人塑造空间，空间反过来塑造人的注意力，这笔账怎么算都是赚的。

邮箱里隔三差五会收到同一类问题：「我也想写博客，但不知道从哪开始。」统一回复成这一篇。先说结论：域名、主题、框架都不重要，第一篇才重要。

三个降低门槛的办法

  • 先写给自己：假设唯一的读者是三年后的你，把踩过的坑记下来就够了；
  • 固定一个小栏目：每周只写一条「本周折腾」，比「我要写深度长文」容易一百倍；
  • 允许烂草稿：先发布，再完美。互联网没有终稿，只有版本。

我的第一篇文章只有两百字，配图还是糊的。但它决定了一件事：我成了「一个写博客的人」。身份先于作品，这是所有长期主义的起点。

五年后回头看，你会拥有唯一一个按时间排序、不可篡改的自己。这件事，社交平台的算法替你保存不了。

默认终端配色是冷的：黑底、冷蓝、荧光绿，那是机房的颜色。可是写代码的地方不该像机房，该像书房——于是某个周末，我把整套开发环境调成了纸的颜色。

一套暖色主题的调法

原则只有三条：背景压暗但不发黑（12、14、18 的暖灰阶），前景用暖白而不是纯白（217、220、227），强调色只保留一种——琥珀。报错的红、警告的黄、成功的绿，全部往琥珀的邻域靠。调完的第一感受：代码没变，但脾气变好了。

后来这个配色蔓延到了编辑器、终端、甚至这个博客。视觉环境是一种慢性的暗示：盯着什么颜色工作八小时，你就会变成什么脾气的工作者。

工具的审美会传染给使用它的人。

这不是一篇教你配色的教程，是一张投票：投给「技术工作也可以是手艺活」的那个选项。

今天是这个博客的一周岁。按照互联网的惯例应该写一篇感恩与数据的总结，但我的 2023 年没有什么增长曲线，只有一张桌子、一盆仙人掌、一台 2015 年的 Kindle，和一个忽然想明白的问题。

为什么要写博客

工作第六年，我发现自己的「折腾」正在贬值：每一周都在解决问题，每一个月都在忘掉解法。折腾若不被写成文字，就和没折腾过差不多。博客对我来说不是媒体，是一个「可供检索的思考」的数据库——读者是副产品，检索未来的自己是主要功能。

慢速缓存的信条

给博客起名的时候想了一晚上。「慢速缓存」取自我给自己定的一条规矩：缓存的东西要长期保鲜，写出来的东西要经得起放。不追热点，不蹭词汇，每一篇都写成三年后回头还愿意承认的样子。

第一年的全部数据：6 篇文章，2 位固定读者——我和我妈。但每一篇都还没有过时。这大概就是这个博客该有的样子。

把代码放在别人硬盘上的感觉，多少有点不安。私有仓库要按月付费，免费平台会扫描你的代码训练推荐——都不是大事，但加在一起就是不舒服。2023 年 6 月的一个晚上，我决定把一块吃灰的树莓派变成家里的 Git 服务器。

树莓派加裸仓库

方案简单得近乎简陋：树莓派插上移动硬盘，建一个裸仓库（git init --bare），本地加一条 SSH 远程，完事。没有 Web 界面，没有 Issue，没有 Star——只有最纯粹的「提交、推送、保平安」。

冷备才是灵魂

单盘不可靠，真正的安心来自冷备：crontab 每周日凌晨把仓库目录打包，同步到另一块不常通电的硬盘，再每月刻一份到家里最角落的柜子。三份数据、两条物理隔离，比大多数云服务的可用性承诺都踏实。

折腾了一晚上，换来十年的踏实。这大概就是自托管的意义：不是省钱，是把「我的东西」四个字重新抓回自己手里。这个博客的第一行代码，就提交在这台小机器上。
