  • 上个月，我在年度计划里写下一行字：把 slowcache.dev 的 LCP 压进 300ms。当时 Lighthouse 给的分数是 45，LCP 是 2.8 秒——对一个自称「关注 Web 性能」的人来说，这多少有点行为艺术。

    一、先测准，再动手

    实验室数据和真实用户数据是两回事。Lighthouse 跑在本地光纤上，而我的读者有一半来自地铁里的 4G。所以我搭了三层测量：Lighthouse 看趋势，WebPageTest 的 4G 节点看弱网，CrUX 看真实用户的第 75 百分位。测了一周，瓶颈排序出乎意料——

    • 全量中文字体 4.2MB，占首屏传输量的 62%，是压垮首屏的头号元凶；
    • 关键 CSS 没有内联，首屏渲染被stylesheet 请求瀑布卡住约 600ms；
    • 三张题图没有懒加载，和字体抢带宽；
    • 一段 80KB 的统计脚本同步加载，阻塞了正文解析。

    二、头号嫌疑人：全量字体

    中文字体是个体积困境：常用字三千五，全量打包动辄几 MB。但我的博客一年也写不满一千五百个不重复的汉字。解法是子集化——用 fonttools 把实际用到的字符削出来，再按 unicode-range 分包，浏览器只下载页面真正用到的那几包。

    bash · subset-fonts.sh
    # 用 fonttools 把 4.2MB 的全量字体削成 84KB
pyftsubset slowcache-full.woff2 \
  --text-file=used-chars.txt \
  --flavor=woff2 \
  --layout-features='kern,liga' \
  --output-file=slowcache-subset.woff2

    第二步是 font-display: swap 配合备用字体的度量对齐（size-adjust / ascent-override），让系统字体先顶上时版式不跳动。这一步做完，FCP 从 1.9s 掉到 0.7s。

    字体体积4.2MB → 84KB
    字体请求数1 → 6 包按需
    FCP1.9s → 0.7s

    三、关键 CSS 内联与首屏直出

    首屏样式只有 11KB，我直接把它内联进 HTML 的 <style>，其余样式异步加载。页面本身由我那个零依赖生成器预渲染成静态 HTML，TTFB 只剩 CDN 的往返。请求瀑布图上，首屏只剩一条几乎垂直的线。

    四、剩下的 100ms：预连接与优先级

    最后一段路最琐碎也最有效：preconnect 提前握手 CDN；LCP 图片加 fetchpriority="high"；统计脚本挪到 requestIdleCallback 里再加载。另外我把缓存策略调成了「慢速缓存」本人：HTML 用 stale-while-revalidate，静态资源带内容哈希加 immutable——名字就是这么来的。

    性能优化的第一原则：先测量，再动手。第二原则：每次只改一件事，否则你永远不知道是谁起了作用。

    最终成绩：LCP 2.8s → 283ms，Lighthouse 45 → 98。回头看，真正难的不是技巧清单，而是克制——忍住不加载第三个第三方脚本，忍住不为一个动效引入 40KB 的库。

    这篇博客的首屏，现在也是 283ms。■

  • 凌晨四点，我被闹钟叫醒。不是为了赶飞机，而是为了赶在杭州醒来之前，先看一眼它没化妆的样子。

    凤起路菜市场的卷帘门，一半还睡着，一半已经哗啦啦地醒了。送货的三轮车停在门口，车上码着的青菜还带着露水，在灯泡底下泛着一层毛茸茸的光。送货的师傅姓周，五十来岁，嗓门不大，但每一句都像盖了章：「芥蓝，今早最好的，你摸摸。」

    豆腐摊的夫妻俩是全市场起得最早的。凌晨两点半磨豆子，四点整第一板豆腐出锅。热气腾起来，把头顶那只白炽灯泡裹成一团毛月亮。女主人用铜刀划豆腐，手起刀落，一块一块，稳得像在执行某种跑了三十年的定时任务。

    我在水产摊前站了很久。增氧泵咕嘟咕嘟地响，鲫鱼挤在一起，尾巴拍出细碎的水花。摊主是个年轻小伙，一边捞鱼一边跟熟客聊天：「同样的鱼，我这里便宜八毛。」熟客说：「我不是图便宜，我是图你这里闹猛。」

    对，闹猛。这个词精确得没法翻译。白天的超市里，价格是印在标签上的；凌晨的菜市场里，价格是聊出来的。抹掉的零头、搭上的两根葱、临走塞进来的一把茴香——这些都是系统的隐藏参数，只在人与人当面通信时才会被激活。

    「菜市场是一座城市的系统日志，而且它每天凌晨四点，准时刷新。」

    五点半，天光从青灰色里渗出来，第一班公交在街口进站。穿反光背心的环卫工、拎着保温杯的摊主、睡眼惺忪的早班乘客，在同一个路口完成交接班。三轮车空了，卷帘门全部醒了，城市正式开始运行。

    我平时写代码，习惯给每个系统记日志。但那个早晨我意识到，没有任何日志比一座菜市场的更诚实——每一次写盘都是真实发生的交易、寒暄和讨价还价，而且从不丢失。■

  • 摘要 — 从铅字的黄金时代讲到可变字体：屏幕分辨率、渲染引擎与「杂志感」回潮背后的技术原因。

    屏幕曾经是衬线体的流放地。72dpi 的年代，衬线被渲染成一团毛边，无衬线体借着「屏幕友好」的名头统治了界面三十年。但 Retina 屏普及、亚像素渲染成熟之后，情况悄悄变了：屏幕终于有能力偿还欠印刷五个世纪的排版债。

    真正让衬线体「活」回来的，是可变字体。一个文件里装下 200 到 900 的连续字重，标题可以像铅字时代的海报一样「又粗又优雅」，正文却依然轻盈。杂志感的回潮不是审美倒车，而是渲染技术终于追上了 1928 年的排印理想。

    这篇观展记从一场活字印刷展讲起，途经 Skia 的可变轴、font-variation-settings 的坑，最后落在一个判断：下一阶段的好排版，是「会呼吸的排版」——字重、字距随交互与滚动轻微起伏，页面像纸一样有生命。

  • 摘要 — animation-timeline 实战笔记：scroll() 与 view() 两套时间轴、6 个渐进增强案例，以及浏览器支持现状。

    滚动驱动动画曾经是 JS 的专属领地：监听 scroll、算比例、写 transform，然后花一半时间处理节流。CSS 滚动时间轴把这一切压缩成两行声明——animation-timeline: scroll() 把动画绑在滚动容器上，view() 把动画绑在元素进入视口的进度上。

    文章用六个案例递进：阅读进度条、分区显影、视差题图、时间轴刻度、图片揭示、以及本站页脚的「回到顶部」环。核心心法只有一条：时间轴是渐进增强，动画消失时内容必须完整可读。

  • 摘要 — 成熟度统计、双链心得与放弃完美主义的收获：一座花园最重要的不是美观，而是「回来找得到」。

    一年前我把博客里「永远写不完」的那些部分搬进了数字花园，用 🌱 幼苗、🌿 成长、🌲 常青三档成熟度公开标注。一年后盘点：214 条笔记里，常青 41 条，成长 97 条，剩下的 76 条还安安静静当幼苗——而且我不再为此羞愧。

    最大的收获是放弃了「发布即完工」的执念。文章是纪念碑，笔记是苗圃；纪念碑要求一次成型，苗圃只要求按时浇水。双链的意义也在这：每条笔记都是入口，回来找得到，比当初写得多好更重要。

    #数字花园#笔记方法#双链

  • 摘要 — 只用 Node 标准库，从 markdown 渲染到增量构建：架构图、踩坑清单，以及为什么不值得你重写一个。

    这个博客就跑在它上面。90 天里我写完了 markdown 解析、模板、增量构建、RSS 输出四个模块，全程只用 Node 标准库——没有 dependencies，连 devDependencies 都没有。npm install 的输出是一句「up to date」，这感觉好极了。

    但文章的结论并不是「你也来写一个」。恰恰相反：写它值 90 天，是因为我想弄懂静态站点生成的每一层；用它则不值 90 分钟，现成工具在 90 秒内就能给你更多。造轮子的回报是理解，不是生产力。

    踩坑清单节选：Windows 路径分隔符、BOM 头、CJK 断行的 CSS 处理、增量构建的脏标记设计，以及 RSS 里那个必须转义八次的 CDATA。

    #Node.js#静态站点#零依赖

  • 摘要 — 越狱、换字体、屏蔽商城，把它改成一台只读文章的墨水屏终端：一次对「设备应有用途」的反抗。

    2015 年买的 Kindle Paperwhite，吃灰三年。它的问题从来不是硬件——墨水屏至今能打——而是软件越来越像一个商场。于是我给它做了次减法手术：越狱、换上思源宋体、屏蔽商店与推荐，最后接上一个每天凌晨抓取我 RSS 列表的脚本，把博客全文推成期刊。

    现在的它是一台纯粹的「慢读终端」：没有通知、没有进度条焦虑，只有每天早上自动出现的一期《慢速缓存》。折腾完我发现，改装旧设备的本质是重新谈判——和厂商谈判设备的用途，也和自己的注意力谈判。

    #Kindle#墨水屏#折腾#数字极简

  • 摘要 — 逐帧拆解三支获奖长文的 pinned 章节、节拍与留白：好的滚动叙事像电影剪辑，而不是过山车。

    我把三个获奖滚动叙事网站逐帧录屏，标注每一次场景切换、每一个 pinned 章节的进入与退出，得出一张「节拍表」。结论朴素得惊人：最好的滚动叙事不是动得最多，而是敢留白——大动效之间必须给眼睛留出静止的落点，像电影里对话之间的沉默。

    文中拆了三种节奏型：匀速纪录片型、章节交响乐型、和最难的「呼吸型」——动效强度随内容情绪起伏。本站的滚动 skew 就是从第三个案例里偷来的，减掉了七成幅度。

    #动效#滚动叙事#案例分析

  • 摘要 — 养了七年仙人掌得出的系统设计心得：最好的照顾，往往是建立一套不需要你时刻干预的环境。

    桌上的仙人掌七岁了，我每年实际照料它的时间不超过两小时。浇水十四天一次，冬天停浇，其余时间它在替我上班——进行「不作为的光合作用」。这份备忘录一半是养护记录，一半是从它身上抄来的系统设计笔记：好的系统不要求操作者勤快，只要求环境不容易被搞坏。

    静态博客、RSS、crontab，本质上都是我养的仙人掌。

  • 摘要 — 写作是为了把折腾过程变成「可供检索的思考」：关于公开笔记本、慢速缓存与长期保鲜的宣言。

    这是本站的创刊号。当时我给博客起的名字叫「字节与纸」，半年后才改成「慢速缓存」。这篇文章记录了改名的原因：缓存的价值不在快，而在「存得住」——写下来的思考是一种对未来的自己的预取。

    宣言只有三条：不追热点、不写没有做过的事、允许文章过时。十年过去，前两条守住了，第三条正在由「半成品」栏目温柔地豁免。

    #创刊#写作动机#RSS

  • 摘要 — 连续一个月坐末班车回家：每条线上的乘客构成、睡眠姿势与城市夜班的隐性时刻表。

    连续一个月，我坐 23:15 之后的末班地铁回城西。末班车是一趟「未收录镜头」列车：代驾师傅折叠着小电驴打盹，夜班护士背靠广告海报站得笔直，兼职下课的学生把整排座位睡成宿舍。车厢安静得能听见空调滴水。

    报告按线路记录了乘客构成与「睡眠姿势图谱」，结论是：末班车从不晚点，它只是载着城市还没说完的话，慢慢进站。

    #杭州#地铁#夜班观察

  • 摘要 — 翻出 2015 年写的第一行 CSS：margin: 0 auto 的浪漫，与这些年在浏览器里学会的谦卑。

    翻硬盘翻出 2015 年的第一个个人主页，全部样式只有一行：margin: 0 auto。十年后的这个博客有两千多行 CSS——其中大概一千九百行在处理第一行那句话没说清楚的事：居中从来不难，难的是「在所有地方、所有人面前」居中。
